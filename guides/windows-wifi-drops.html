Diagnosis / GUIDE NO. 05

Windows laptop keeps dropping Wi-Fi: capture evidence first

Windows can record a useful history of Wi-Fi sessions. Review it before deleting profiles or resetting the network stack.

SignalNook EditorialReviewed 11 Nov 2026
THE SHORT ANSWER

Windows can record a useful history of Wi-Fi sessions. Review it before deleting profiles or resetting the network stack. Begin with a repeatable comparison and record one change at a time, rather than making several router changes together.

When the connection drops

Record whether the entire Wi-Fi icon disconnects, the browser merely loses internet, or only a VPN or meeting app fails. Note a rough timestamp and whether the laptop was waking from sleep, moving between rooms, or switching to battery power. Those details help separate roaming and driver behavior from ISP interruptions.

Generate the built-in report

On supported Windows versions, open Command Prompt with suitable permissions and run `netsh wlan show wlanreport`. Windows produces an HTML report of recent wireless events and provides a location to open it. The report can include session outcomes, disconnect reasons, adapter details and recent events. Because it contains network identifiers and system information, keep it private and redact identifying details before sharing a screenshot.

Compare the conditions

Test near the router, then in the failing room. If the issue happens after sleep even near the router, review driver, power management and OS updates with the laptop manufacturer. If it happens when you walk between mesh points, roaming behavior deserves attention. If other devices fail at exactly the same time, examine the router and ISP instead of assuming the laptop alone is responsible.

Avoid destructive “fix everything” steps

Deleting all saved networks, removing a wireless adapter or performing a full network reset can hide clues and disrupt work accounts. Microsoft recommends collecting a baseline and the reproduction time before resets. Update drivers from the laptop or adapter vendor, not unknown download portals, and record the previous version before changing anything.

Close the loop

After a targeted update or configuration change, observe several sleep/wake cycles and ordinary use at the location where the issue happened. A single successful connection is not enough to show the intermittent problem is resolved. Write down what changed and the time of the next test.

A worked example

Example: a laptop disconnects after waking, while phones work. Its report repeatedly shows a disconnect around resume events. That narrows the next investigation toward driver and power-state behavior.

How to interpret three common observations

The same visible symptom can have more than one cause. Use the comparisons below as test priorities, not as an automatic diagnosis of your particular equipment.

Every drop follows waking from sleep

Compare adapter and power-state events in the Windows wireless report. A client driver or resume behavior deserves attention.

Drops occur when walking between access points

Log room and time, then check roaming and mesh placement rather than assuming the internet service itself fell.

Other devices also drop at identical times

Move beyond Windows-specific changes and inspect the shared router, ISP and local interference patterns.

Field checklist

  • Write down the moment of disconnection
  • Generate a Windows wireless report
  • Check same room on other devices
  • Compare before/after sleep
  • Change one supported setting at a time
Don't make this mistake

Do not post raw wireless reports publicly; they can contain device and network identifiers.
