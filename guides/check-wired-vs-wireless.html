Planning / GUIDE NO. 15

How to compare Ethernet and Wi-Fi without bad conclusions

Two controlled tests can show whether the weak link is radio coverage or upstream service—but only if you account for hardware limits.

SignalNook EditorialReviewed 11 Nov 2026
THE SHORT ANSWER

Two controlled tests can show whether the weak link is radio coverage or upstream service—but only if you account for hardware limits. Begin with a repeatable comparison and record one change at a time, rather than making several router changes together.

Know what Ethernet isolates

A cable from a laptop to the router removes the local Wi-Fi radio segment from the path. It does not bypass the ISP, gateway CPU, or an unreliable modem. If wired performs well while the same laptop on Wi-Fi performs badly, investigate radio factors. If both are poor, examine shared components before moving access points.

Check port and cable limits

A 100 Mbps Ethernet port cannot measure a gigabit plan accurately. The network adapter, switch, docking station, and cable must support the desired speed. A damaged connector may negotiate to a lower link rate. Check the negotiated link speed rather than assuming an Ethernet cable is automatically fast. This is especially relevant when using USB adapters or older office docks.

Control test conditions

Try to run both tests within a short window with little household traffic, using the same laptop and test service. Repeat a few times and note download, upload and latency. Do not take a single maximum as the average. If the room is far from the router, add a near-router Wi-Fi test so you can see whether distance matters.

Interpret the pattern

Wired strong / near Wi-Fi strong / far Wi-Fi weak suggests a location or coverage problem. Wired strong / near and far Wi-Fi weak suggests interference, router radio or client capability. Wired weak / Wi-Fi weak suggests upstream or local wired equipment. These are hypotheses, not definitive fault labels; verify using additional devices or vendor diagnostics.

Keep raw evidence private

Record the time, location and numeric results in the Speed Log; do not upload logs containing private device names or internal IP addresses to untrusted sites. The SignalNook log is stored only in this browser and can be exported if you choose. No website calculator can infer the true cause of slowness from one number alone.

A worked example

Example: wired via a modern gigabit port reaches 450 Mbps, Wi-Fi nearby reaches 390, and a back office reaches 35. That suggests the room path is the best next experiment; upgrading from a 500 Mbps plan would be a poor first response.

How to interpret three common observations

The same visible symptom can have more than one cause. Use the comparisons below as test priorities, not as an automatic diagnosis of your particular equipment.

Wired 450, near Wi-Fi 390, far Wi-Fi 35 Mbps

The remote-room path is the clearer target. Reposition the access point and repeat under similar load.

Wired and near Wi-Fi both 80 on a 500 Mbps plan

Check negotiated Ethernet speed, port limits and provider status before blaming radio interference.

Call quality poor despite 400 Mbps down

Test upload responsiveness and competing transfers; raw download throughput does not capture every real-time issue.

Field checklist

  • Confirm Ethernet negotiated speed
  • Use the same test service and device
  • Test wired, near-router and remote room
  • Repeat under similar household load
  • Log date, location, connection and results
Don't make this mistake

Do not compare a 100 Mbps adapter result with a modern Wi-Fi radio without considering the hardware bottleneck.
